# Dataset Note

## Phase 1: Parsing
**Actual Format Discovered**
The `mobility.tcl` file contains NS-2 mobility trace format generated by SUMO. The movement commands are explicitly timestamped using the syntax:
`$ns_ at <time> "$node_(<id>) setdest <x> <y> <speed>"`
Initialization commands without speed or explicit timestamps (e.g., `set X_`) were skipped because `$ns_ at 0.0` completely defines the initial position vectors.

**Meaning of Parsed Columns**
- `time` (float): The simulation timestamp (seconds).
- `vehicle_id` (int): The unique integer ID assigned to the node/vehicle.
- `x` (float): The X-coordinate position of the vehicle.
- `y` (float): The Y-coordinate position of the vehicle.
- `speed` (float): The target speed of the vehicle (m/s).

## Phase 3: Dynamic Graph Construction

**1. Time-window size**
10 seconds.

**2. Window step**
10 seconds.

**3. Window boundary convention**
Half-open intervals `[start_time, end_time)`. This ensures no single record falls into two adjacent windows.

**4. Vehicle snapshot method**
Within each time window, the representative spatial state for a vehicle is its **last valid observation** before the end boundary of the window. This preserves causality and prevents temporal leakage.

**5. Node definition**
Each node represents a distinct vehicle present within the given time window, identified uniquely by `vehicle_id`.

**6. Node features**
Unscaled, canonical physical properties: `[x, y, speed, time]`.

**7. Distance formula**
2D Euclidean spatial distance: `sqrt((x_i - x_j)^2 + (y_i - y_j)^2)`.

**8. Coordinate units**
Meters (m).

**9. Communication range**
200 meters.

**10. Edge definition**
An undirected connection is created if the Euclidean distance between two vehicles is <= 200m. No self-loops (a vehicle does not connect to itself).

**11. Directed/undirected graph**
Undirected graph.

**12. Weighted/unweighted graph**
Unweighted graph structure conceptually (edge weight=1), though the actual Euclidean distance is saved as edge metadata `distance` for potential future weighted modeling.

**13. Graph storage format**
Python `.gpickle` format retaining full NetworkX structures containing nodes, edges, and rich attribute dictionaries perfectly formatted for PyTorch Geometric conversion.

**14. Graph validation rules**
All generated graphs are computationally checked to ensure:
- No self-loops exist.
- No edges violate the communication range threshold (d > 200m).
- Every node has valid coordinates.

## Phase 4: K-Means Baseline

**1. Input graph representation**
The model loads the NetworkX graphs serialized in `.gpickle` format directly from Phase 3, extracting nodes to create feature vectors and iterating over edges for topological evaluation post-clustering.

**2. Node features**
Feature vectors are constructed purely from physical vehicle parameters `[x, y, speed]` extracted from the canonical graph nodes. No structural graph features are included, strictly maintaining K-Means as a feature-space baseline.

**3. Feature scaling**
Features are standardized per graph snapshot using `StandardScaler` to handle unit differences (m vs m/s). Scalers are fit independently per window to maintain temporal independence and prevent data leakage from future windows.

**4. K value**
Configured to `k=5` via `configs/config.yaml`.

**5. Random seed**
`random_state=42` is strictly enforced to ensure reproducibility of the algorithm across executions.

**6. n_init**
`n_init=20` sets the number of distinct random centroid initializations.

**7. Maximum iterations**
`max_iter=300`.

**8. K-selection procedure**
Diagnostic k-selection evaluates values `K=2..10` (or `n-1` for tiny graphs) for selected representative windows. Results are stored in `kmeans_k_selection.csv` using Silhouette, Davies-Bouldin, and Calinski-Harabasz metrics to guide subsequent analysis.

**9. Evaluation metrics**
Clustering quality in feature space is assessed per-window using:
- Silhouette Score
- Davies-Bouldin Index
- Calinski-Harabasz Score
- Intra-cluster Mean Euclidean Distance

**10. Graph-topology evaluation**
After the K-Means assignments are generated independently of graph edges, the resulting clusters are structurally evaluated against the Phase 3 communication graph to check:
- Total internal edges (nodes in the same cluster communicating)
- Total external edges (communication across cluster boundaries)
- Internal edge ratio (Internal / Total)

**11. Temporal-overlap preparation**
Vehicle retentions (`common_vehicle_count`) between `[t, t+1]` windows are pre-calculated to facilitate future Hungarian matching and actual cluster stability analysis.

**12. Limitations of K-Means for VANET graphs**
**Explicit limitation:** K-Means does not directly model or optimize over graph connectivity. It only discovers Euclidean relationships in `[x, y, speed]` space. A highly dense K-Means cluster may theoretically contain vehicles that are out-of-range for direct communication. Topology evaluation results are purely post-hoc descriptions, and K-Means is implemented solely as an initial baseline for future GNN evaluations.

## Phase 5: Spectral Clustering Baseline

**1. Input graph representation**
The model uses the same NetworkX communication graphs directly generated from Phase 3. The adjacency representation is strictly binary and unweighted (edge = 1, no edge = 0).

**2. Adjacency matrix definition**
Symmetric $N \times N$ matrix. $A_{ij} = 1$ if Euclidean distance $\le 200m$, else $0$. Zero self-loops ($A_{ii} = 0$).

**3. Graph type**
Undirected.

**4. Laplacian definition**
Normalized symmetric Laplacian: $L_{sym} = I - D^{-1/2} A D^{-1/2}$. Isolated nodes with degree zero are safely handled.

**5. Affinity definition**
Precomputed binary adjacency matrix directly encodes VANET connectivity. No physical features (`[x, y, speed]`) are included in the affinity matrix, isolating Spectral Clustering as a purely graph-structural baseline.

**6. Number of clusters**
$K = 5$, identically comparable to K-Means. 

**7. Random seed**
`random_state=42` ensures deterministic clustering assignments during K-Means internal assignment step.

**8. n_init**
`n_init=20` ensures robust eigenvalue convergence labels.

**9. K-selection procedure**
Spectral K-selection evaluates values $K=2..10$ across representative windows.

**10. Eigenvalue analysis**
The first 20 eigenvalues of the normalized Laplacian and their eigengaps are explicitly calculated and recorded to track spectral graph properties.

**11. Graph-topology metrics**
Evaluated per-window:
- Total internal/external edges
- Internal edge ratio
- Modularity (via `networkx`)
- Cluster conductance

**12. Feature-space metrics**
For direct comparison with K-Means, Silhouette Score, Davies-Bouldin Index, and Calinski-Harabasz Score are computed on scaled `[x, y, speed]` features, purely as a post-hoc evaluation.

**13. Temporal-overlap preparation**
Precalculated the intersection and Jaccard similarity between clusters across sequential snapshots $t \to t+1$.

**14. Limitations**
Spectral embedding often emits warnings when operating on disconnected graph components (a common physical reality in VANETs). The implementation safely handles these disconnected topologies without artificially coercing connectivity, acknowledging this baseline limitation on realistic routing scenarios.


## Phase 6: Graph Autoencoder (GAE)

### 1. Input Node Features
- Dimension: 3
- Features: `[x, y, speed]`
- Preprocessing: StandardScaling fitted per-window.

### 2. Graph Representation
- Edges based on 200m physical communication range, encoded as PyTorch Geometric `edge_index` (undirected, therefore symmetric entries in `edge_index`).

### 3. Encoder Architecture
- Framework: PyTorch Geometric
- Layers: 2x GCNConv
- Layer Dimensions: `3 -> 64 -> 16`
- Activation: ReLU after first layer.

### 4. Latent Dimension
- `Z` belongs to R^16.

### 5. Decoder
- Inner-product decoder computing `A_hat = sigmoid(Z Z^T)` to reconstruct graph topology.

### 6. Reconstruction Target
- Original unweighted VANET adjacency matrix.

### 7. Reconstruction Loss
- Binary Cross Entropy (BCE) over all pairs of nodes.
- A positive edge weight `pos_weight` is dynamically calculated per window to combat sparsity (`pos_weight = negative_edges / positive_edges`).

### 8. Positive-Class Handling
- Evaluated using ROC-AUC and Average Precision (ignoring self-loops) directly on the decoder output against actual edges.

### 9. Optimizer
- Adam Optimizer.

### 10. Learning Rate
- 0.01 with weight decay of 0.0001.

### 11. Epochs
- 200 epochs maximum per window.

### 12. Early Stopping
- Triggered if reconstruction BCE loss does not improve for 20 epochs.

### 13. Random Seed
- Set to 42 for NumPy and PyTorch (CPU and CUDA).

### 14. Clustering Procedure
- K-Means with K=5, `n_init=20`, `random_seed=42`, applied natively to the learned 16D latent embeddings.

### 15. Evaluation Metrics
- Modularity and internal-edge ratio against the original graph.
- Silhouette, Davies-Bouldin, and Calinski-Harabasz evaluated in the latent space.

### 16. Temporal-Overlap Preparation
- Conducted a forward scan matching cluster overlap across `t` and `t+1` windows using Jaccard Similarity to prepare for Hungarian matching.

### 17. Limitations
- The inner product decoder forces an O(N^2) dense reconstruction matrix. While computationally fine for current N~500 networks, highly dense environments will mandate negative sampling optimization.
